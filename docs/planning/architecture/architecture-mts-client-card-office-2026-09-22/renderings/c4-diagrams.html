C4-модель · card-office · МТС Банк

Context → Container → Component

Три уровня C4 для бэкенда клиент-карточного офиса: система целиком, контейнеры внутри неё, и один сервис (risk-blocks) — на уровень глубже. Источник — ARCHITECTURE-SPINE.md (final).

1. Context — система целиком

Сотрудник офиса работает через существующий React-фронтенд, который вызывает бэкенд card-office (объект этой архитектуры). Бэкенд, в свою очередь, обращается к пяти внешним системам банка — сегодня через заглушки (AD-10), в проде это будут реальные интеграции.

2. Container — что реально разворачивается

Внутри границы «Card-office backend» — Gateway, девять сервисов (каждый со своей PostgreSQL, AD-1) и Kafka, у которой единственный подписчик — incident-case. Ни одной стрелки между девятью сервисами нет — это диаграмма правила AD-9, а не упрощение.

3. Component — risk-blocks-service изнутри

risk-blocks выбран как самый показательный сервис: один контейнер фасадом закрывает сразу три независимые внешние системы через три раздельных порта (AD-10). Слои — точно по hexagonal-layout спины: adapters/in/web → application → domain (сущность + порты) → adapters/out (persistence + external).
